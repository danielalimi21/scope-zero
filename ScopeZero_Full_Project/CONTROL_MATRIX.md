# ScopeZero Control Matrix

This is an internal engineering control matrix. It maps each runtime control to the code path that actually enforces it. Keep it blunt: if a control is deterministic, fallback-only, or not yet production-grade, say so here.

| Control | Code path | What it actually does | Current limitation |
| --- | --- | --- | --- |
| Mission capsule signature | `src/runtime.js`, `src/capsules.js`, `src/crypto.js` | Blocks tool calls when the mission capsule is missing, expired, or fails Ed25519 signature verification. Private key signs at the gateway; verifiers hold only the public key and cannot forge. | KMS/HSM-held private key is a documented seam, not yet wired (the supported prod path is a PEM private key, which the boot gate now enforces). |
| Fail-closed boot | `src/startupGate.js`, `server.js` | In production the gateway refuses to start without an explicit `SCOPEZERO_SIGNING_PRIVATE_KEY`, a non-default ledger secret, a declared `SCOPEZERO_EGRESS_LOCKDOWN` (k8s\|docker), auth required, and dev tokens off. Closes the "secure only if configured" gap by making misconfiguration non-bootable. **The egress lockdown is also PROVEN at boot, not just declared:** when a lockdown is declared in production, `server.js` opens a raw socket to a canary host from its own namespace and refuses to start if egress is actually open (`SCOPEZERO_SKIP_EGRESS_BOOT_CHECK=true` overrides mid-rollout, logged loudly). | The gateway's own namespace legitimately has egress in some topologies; for the agent namespace specifically, also run `tools/lockdown-selftest.js` inside the agent pod. |
| Signing-key rotation | `src/crypto.js`, `src/capsules.js`, `src/agentCert.js`, `src/runtime.js` | Capsules/certs carry a `kid`; verification runs against a keyset (current + retired public keys via `SCOPEZERO_SIGNING_PUBLIC_KEYS`), so the signing key can rotate without invalidating live artifacts. `tools/gen-keys.js` generates keypairs. | Operator must add the retiring public key to the keyset for the overlap window. |
| Egress-lockdown self-test | `tools/lockdown-selftest.js`, `src/egressSelftest.js` | Opens a raw off-path socket from inside the agent's network namespace and reports `contained`/`open`. **OPEN egress exits non-zero whenever containment is expected** — a lockdown is declared (`SCOPEZERO_EGRESS_LOCKDOWN=k8s\|docker`), `NODE_ENV=production`, or `--expect-contained` — so a declared-but-not-applied lockdown fails the check instead of passing silently. Pure dev with no lockdown declared stays observational (exit 0); `--allow-open` overrides mid-rollout. Exit-code policy unit-tested in `tests/egress-selftest.test.js`. | Must be run inside the actual agent namespace to be meaningful — the gateway itself legitimately has egress, so this cannot be a gateway-boot probe. |
| Require-proxy-path | `server.js` | Optional (`SCOPEZERO_REQUIRE_PROXY_PATH`): rejects tool calls lacking the enforced-ingress marker header, catching an agent that skipped the SDK/proxy to hit the gateway directly. | Does not catch a raw socket that skips the gateway entirely — that is the kernel lockdown's job. |
| Supply chain | `.github/workflows/scopezero-ci.yml`, `package.json` | CI runs `npm audit` (high+ fails), generates a CycloneDX SBOM artifact, and has a keyless-cosign image-signing job. | Image signing needs a target registry wired; external pen-test is out of scope of the repo. |
| Tool allowlist | `src/policyEngine.js` | Escalates when a requested tool is outside the mission allowlist. | Tool identity still depends on the caller sending the correct tool id. |
| Mission action contracts | `src/actionAuthorization.js`, `src/policyEngine.js` | Blocks tools, operations, data classes, and destinations outside the signed mission contract. | Contract quality depends on correctly authored missions. |
| Tool manifest classification | `src/toolManifest.js`, `src/actionAuthorization.js`, `src/connectors.js` | Uses registered connector manifests as the authoritative operation/action type source before any regex fallback. | Unregistered tools still use fallback inference and should be treated as lower trust. |
| Data boundary | `src/sensitiveData.js`, `src/policyEngine.js` | Classifies payloads deterministically and blocks when the class exceeds mission or policy boundaries. | Deterministic checks are shallow compared with enterprise DLP. |
| Destination boundary | `src/sensitiveData.js`, `src/actionAuthorization.js`, `src/policyEngine.js` | Detects external destinations and enforces mission/policy destination allowlists. | Destination classification is rule-based. |
| Prompt influence (advisory) | `src/sensitiveData.js`, `src/policyEngine.js` | Scores configured patterns, paraphrased instruction override, bypass, exfiltration, concealment, leetspeak, homoglyph, and likely base64-encoded prompt influence. **Raises risk / quarantines context; does not block on its own.** | Denylist classifier, not embedding/model-graded — novel phrasings and other languages slip it. Sold as a signal, not the control. |
| Server-side mission alignment (advisory) | `src/missionAlignment.js`, `src/runtime.js`, `src/policyEngine.js` | Compares requested operation/action/destination against the signed mission objective server-side instead of trusting the agent's `mission_aligned` flag. **Routes drift to human approval; never blocks on its own.** | Keyword-overlap heuristic, gameable by padding; not semantic understanding. The deterministic contract gates are what block. |
| Unknown-egress fail-closed | `src/policyEngine.js`, `src/sensitiveData.js` | Holds for human review any outbound content whose data class can't be positively established *from the bytes* — the keyword classifier found nothing AND the payload has a bulk/tabular/encoded/large shape (`classifyPayload` shape analysis). A tool manifest's `data_out_classes` is a **verified ceiling**, not a skip-flag: if the payload classifies above the declared output class the manifest is contradicted by the bytes and the call escalates (`manifest-output-class-exceeded`); a manifest declaring "public" cannot wave through opaque bytes. Catches exfiltration to an in-contract host through **any** tool, manifested or not, that the host-only proxy can't see. | Shape analysis is heuristic — it catches bulk/tabular/encoded dumps, not low-volume sensitive values laundered inside natural prose. That laundering residual is now covered by the **default-on external-egress seal** (below), which holds external posts regardless of byte establishment unless the destination is a declared public sink. Not a substitute for enterprise DLP. |
| Ingest-taint / anti-laundering | `src/policyEngine.js`, `src/runtime.js`, `src/store.js` | Tracks a monotonic high-water mark of the most sensitive data class a *mission* has been exposed to (outbound payload AND inbound context/retrieved docs). When a mission that has ingested data at or above `ingest_taint_block_level` (default `confidential`) then sends *lower-classed* content to an external destination, the egress is held for human review — because laundered content (sensitive data the model rewrote into benign-looking prose) leaves looking benign and no content classifier can catch it. Judges egress by what the mission touched, not just the outbound bytes. **Taint is keyed at MISSION scope, not on the caller-supplied `session_id`** — `mission_id` is server-resolved and Ed25519-bound, so a prompt-injected agent cannot reset accrued taint by rotating the session string (effective taint = `max(session, mission)`, verified in `tests/egress-integrity.test.js`). | Only sees material that passes through the gateway (payload or declared context); a tool result returned straight to the agent without ever being shown to ScopeZero is not tainted — that residual is what the egress seal (below) covers. Cross-mission laundering (read under mission A, exfil under a separate valid mission B) requires the attacker to already hold a second signed mission whose contract permits the external destination; the contract gate bounds that. Fires on class *downgrade* to external only. |
| External-egress seal (default ON) | `src/policyEngine.js`, `src/capsules.js` | `seal_external_egress` (**default on**): every meaningful external egress is held for human review **unless its destination is an explicitly declared public-broadcast sink** (`public_egress_ok: true` on the contract, or the mission's `public_egress_destinations`). This is the honest fail-closed posture and is **decoupled from the mission's data clearance** — a narrow public/internal mission gets the same protection as a confidential one, so narrowing a mission can never *reduce* its egress protection. It closes the residual neither the byte-classifier nor ingest-taint can see: a secret read out-of-band and laundered into benign prose on a never-tainted session classifies as "established public", so byte-establishment cannot be the all-clear. Autonomy on an external lane is an explicit, signed, auditable opt-in — not the default. Verified in `tests/egress-default-seal.test.js`. | Trades approvals for assurance: external posts need a human unless the destination is a declared public sink. Laundering *to a destination you marked a public sink* is your audited decision and is not caught — that one trusted lane is the only thing the seal yields. |
| Sensitive-mission egress seal (opt-in) | `src/policyEngine.js` | `seal_sensitive_mission_egress` (default off): the narrower, clearance-gated variant of the seal above — when a mission is cleared for confidential/restricted data, all of its meaningful external egress is held. Largely subsumed by the default-on `seal_external_egress`; kept for operators who want the seal to apply *only* to confidential-cleared missions. Verified in `tests/egress-classifier.test.js`. | Clearance-gated, so a narrow mission gets no protection from this row alone — that is exactly why `seal_external_egress` defaults on. |
| Destination external floor | `src/sensitiveData.js` (`isExternalDestination`) | "External" is established from the destination address against the policy `trusted_destinations` list. A caller may ASSERT `external: true` (raise), but may NOT assert `external: false` to suppress the egress guards — a self-declared "internal" flag never overrides an untrusted address. Fail-closed: an unknown/untrusted target is treated as external. Verified in `tests/egress-integrity.test.js`. | Internal hosts must be listed in `trusted_destinations`; an unlisted internal host is treated as external (safe direction, may add an approval). |
| Structured value detection | `src/sensitiveData.js` | Classifies a sensitive *value* by its structure with no topic keyword nearby: Luhn-validated card numbers, IBAN, dashed SSN, known credential shapes (`AKIA…`/`ASIA…`, `ghp_`/`gho_`/`ghs_`/`github_pat_`, `glpat-`, `xox…`, `sk-`/`sk_live_`/`rk_live_`, `AIza…`, `ya29.`, JWTs, PEM private keys), and high-Shannon-entropy tokens. **Card detection accepts any common separator (space, dash, dot)** with Luhn as the false-positive gate, so `4012.8888.8888.1881` no longer evades it. **The classifier also decodes base64/hex tokens embedded in the payload and re-scans them**, so a credential wrapped in a trivial encoding (under the bulk-blob shape threshold) is still caught — matching the decode the prompt-influence path already does. Closes the "a secret/PAN dropped into otherwise-benign prose" gap the keyword classifier misses. | Heuristic; thresholds are conservative to avoid flagging UUIDs/ordinary identifiers. Deliberately does **not** match a bare 9-digit run as an SSN (every order/account number is 9 digits — unacceptable false-positive rate); contextual SSN-without-dashes is the external classifier's job — but the default-on egress seal now holds such egress regardless. Not a full DLP value catalog. |
| Pluggable classifier | `src/runtime.js`, `src/sensitiveData.js` | `classifierResolver` injection point lets an embedding / model-graded / commercial-DLP classifier augment the deterministic one. The external verdict is merged as a ceiling-raiser — it can only raise the class / establish sensitivity, never lower it below what the bytes already established. | The default build ships only the deterministic regex+shape classifier; non-English and semantic coverage depend on the integrator wiring a real classifier. |
| Egress-lockdown posture | `tools/config-check.js`, `server.js` (`/v1/ready`) | Surfaces whether a kernel-level egress lockdown is declared (`SCOPEZERO_EGRESS_LOCKDOWN=k8s\|docker`). `config-check` fails the production check and `/v1/ready` reports `egress_lockdown: none` when undeclared, so the honor-system bare-SDK tier is loud, not silent. | The app cannot enforce deployment topology; it can only require the operator to declare it and flag the gap. |
| Manifest-required mutation | `src/policyEngine.js`, `src/actionAuthorization.js` | Escalates any mutating/high-impact operation that has no authoritative tool manifest, since the operation is otherwise the agent's self-declared word. | Coverage improves as connectors register manifests; unregistered mutating tools always escalate. |
| High-impact action approval | `src/policyEngine.js` | Escalates high-impact action types such as export, external send, privilege change, payment, and delegation. | Depends on action type quality; tool manifests now improve this for registered tools. |
| Runtime risk budget | `src/policyEngine.js`, `src/runtime.js`, `src/store.js` | Accumulates session risk and escalates when a session would exceed its budget. **Keyed at MISSION scope (like ingest-taint):** effective risk = `max(session, mission)`, raised under both keys after each decision, so a prompt-injected agent cannot reset the accumulated budget by rotating the caller-supplied `session_id`. Verified in `tests/egress-default-seal.test.js`. | No learned behavioral baseline yet (the behavior analyzer covers burst/velocity/volume separately). |
| Decision cache | `src/runtime.js` | Caches repeated equivalent decisions for a short TTL using mission, policy, tool, operation, data class, destination, privilege, money, and risk bucket. | In-memory per process; not a distributed cache or sidecar yet. |
| Tenant isolation | `db/postgres/schema.sql`, `src/postgresStore.js` | Mirrors runtime state into tenant-scoped Postgres tables protected by row-level security using `scopezero.tenant_id`. | The canonical `scopezero_state` document remains a service-only maintenance table and must not be exposed to tenant roles. |
| Evidence ledger | `src/ledger.js`, `src/runtime.js` | Appends hash-chained decision evidence for missions, approvals, and authorization decisions. | Local JSONL remains the primary demo ledger. |
| Ledger external anchor | `src/ledgerAnchor.js`, `src/ledger.js` | Optionally writes signed chain roots to a separate file or external witness endpoint using `SCOPEZERO_LEDGER_ANCHOR_FILE` or `SCOPEZERO_LEDGER_ANCHOR_URL`. | Not a full S3 Object Lock integration yet unless the endpoint/file target is backed by immutable storage. |
